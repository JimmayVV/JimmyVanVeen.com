Context: React Router v7 SSR on Netlify, React 19, Tailwind v4, editorial paper/midnight-ink design, strict TS with `as` banned. Sizes marked "measured" were downloaded from unpkg/GitHub and gzipped locally today; the rest cite bundlephobia's API or the vendor's docs.

## Notes per technique

**1. CSS scroll-driven animations.** `animation-timeline: scroll()` / `view()` with `animation-range` (`entry`, `exit`, `cover`, ...) runs off the main thread ([Chrome docs](https://developer.chrome.com/docs/css-ui/scroll-driven-animations)). caniuse: Chrome/Edge 115+, Safari and iOS 26+, Firefox 157, 85.43% global ([caniuse](https://caniuse.com/mdn-css_properties_animation-timeline)); MDN still labels it "Limited availability" ([MDN](https://developer.mozilla.org/en-US/docs/Web/CSS/animation-timeline)). Firefox 155 shipped today and 157 lands 2026-09-29 ([Firefox calendar](https://whattrainisitnow.com/calendar)), so within a month the only gap is old Safari. Polyfill: flackr's `scroll-timeline-polyfill` 1.1.0, Apache-2.0, `dist/scroll-timeline.js` 60.9 KB min / 16.7 KB gzip, `-lite` 9.4 / 5.3 KB (measured); it requires CSS to be same-origin or inline ([repo](https://github.com/flackr/scroll-timeline)). Recommendation: skip the polyfill and use `@supports (animation-timeline: scroll())` with a time-based keyframe fallback.

**2. Pure CSS keyframes on inline SVG with `offset-path`.** `offset-path` is Baseline widely available since March 2022 ([MDN](https://developer.mozilla.org/en-US/docs/Web/CSS/offset-path)); caniuse: Chrome 46, Firefox 72, Safari/iOS 16, 95.64% ([caniuse](https://caniuse.com/css-motion-paths)). `offset-rotate: auto` turns the sprite to follow the path direction, Baseline since Sept 2022 ([MDN](https://developer.mozilla.org/en-US/docs/Web/CSS/offset-rotate)). Zero JS, the SVG is in the server HTML so there is nothing to hydrate, and `transform`/`offset` animations don't cause layout shift ([web.dev CLS](https://web.dev/articles/cls)). Reduced motion is one `@media` block ([MDN](https://developer.mozilla.org/en-US/docs/Web/CSS/@media/prefers-reduced-motion)). Combine with technique 1 by swapping `animation-timeline` in under `@supports`.

**3. Web Animations API driven by scroll.** `Element.animate()` plus `animation.currentTime` scrubbing is documented on MDN ([Using the WAAPI](https://developer.mozilla.org/en-US/docs/Web/API/Web_Animations_API/Using_the_Web_Animations_API)); passing `timeline: new ScrollTimeline(...)` has the same support as row 1 ([caniuse](https://caniuse.com/mdn-api_scrolltimeline)). Where `ScrollTimeline` is missing you fall back to a `scroll` listener + rAF on the main thread. Must live in `useEffect`, gate on `matchMedia("(prefers-reduced-motion: reduce)")`, and type-guard `"ScrollTimeline" in window` rather than assert. Only worth it if you need something CSS can't express (e.g. speed reacting to scroll velocity).

**4. Rive.** Runtimes are MIT and React 19 is in the peer range (`@rive-app/react-canvas` 4.33.0). Measured cost: `@rive-app/canvas-lite` 406 KB JS / 87 KB gzip + 770 KB / 313 KB gzip WASM; full `canvas` 427 / 95 KB + 1.81 MB / 747 KB WASM; `webgl2` WASM 818 KB gzip. The React hooks do all canvas work in `useEffect` ([useRive.tsx](https://github.com/rive-app/rive-react/blob/main/src/hooks/useRive.tsx)), so SSR emits an empty canvas. The blocker is the editor: since 2025-10-20 "Exports move to paid plans"; the Free plan cannot export `.riv`, Cadet is $9/mo annual or $17 monthly ([Rive blog](https://rive.app/blog/rive-s-new-9-mo-plan), [pricing](https://rive.app/pricing), [export docs](https://rive.app/docs/editor/exporting/exporting-for-runtime)). Fails the "stay free" constraint.

**5. Lottie.** `lottie-web` 5.13.0 is 306 KB / 76.8 KB gzip ([bundlephobia API](https://bundlephobia.com/api/size?package=lottie-web)); the `lottie_light.min.js` SVG-only build is 168 KB / 46.4 KB gzip (measured). `@lottiefiles/dotlottie-web` 0.80.0 is 165 KB / 32.9 KB gzip JS but fetches a "~500 KB compressed" WASM from its CDN on first construction (measured 1.24 MB / 496 KB gzip; self-host with `setWasmUrl`) ([README](https://github.com/LottieFiles/dotlottie-web/blob/main/packages/web/README.md)). No lighter official player exists. All MIT; `lottie-react` and `@lottiefiles/dotlottie-react` declare React 19 peers. Pointless for a single car sprite you could draw as SVG.

**6. Motion and GSAP.** Motion 13.1.1, MIT, peers `react ^18 || ^19`; bundlephobia 135.7 KB / 45.3 KB gzip for everything, but the docs put `<motion.*>` at 34 KB min, `m` + `LazyMotion` at 4.6 KB initial and `useAnimate` mini at 2.3 KB ([reduce bundle size](https://motion.dev/docs/react-reduce-bundle-size)). It runs scroll-linked animations on native `ScrollTimeline` where available ([scroll docs](https://motion.dev/docs/react-scroll-animations)) and ships `MotionConfig reducedMotion="user"` + `useReducedMotion` ([accessibility](https://motion.dev/docs/react-accessibility)). GSAP 3.15.0 became "100% FREE including ALL of the bonus plugins" on 2025-04-29 under Webflow; the Standard License permits commercial use, the only restriction being no-code animation tools that compete with Webflow ([3.13 post](https://gsap.com/blog/3-13/), [license](https://gsap.com/community/standard-license/)). Measured: `gsap.min.js` 72.9 / 28.3 KB gzip, `ScrollTrigger.min.js` 44.6 / 18.0 KB. ScrollTrigger debounces `scroll` events onto rAF, i.e. main thread, not native scroll timelines ([docs](https://gsap.com/docs/v3/Plugins/ScrollTrigger/)); `@gsap/react` 2.1.2 (`react >=17`) `useGSAP` falls back to `useEffect` when `window` is undefined ([React guide](https://gsap.com/resources/React/)).

**7. View Transitions API.** Same-document `document.startViewTransition` is Baseline Newly available since Oct 2025 ([MDN](https://developer.mozilla.org/en-US/docs/Web/API/Document/startViewTransition)); caniuse Chrome 111, Safari 18, Firefox 144, 90.2% ([caniuse](https://caniuse.com/view-transitions)). Cross-document `@view-transition { navigation: auto }` is Chrome 126, Safari 18.2, no Firefox, 84.8% ([caniuse](https://caniuse.com/mdn-css_at-rules_view-transition), [Chrome](https://developer.chrome.com/docs/web-platform/view-transitions/cross-document)). React Router framework mode renders client-side after hydration ([rendering](https://reactrouter.com/start/framework/rendering)), so the same-document path is what matters: `<Link viewTransition>`, `navigate(to, { viewTransition: true })`, `useViewTransitionState(to)` and the `isTransitioning` render prop, with `view-transition-name` in CSS; unsupported browsers just navigate ([how-to](https://reactrouter.com/how-to/view-transitions), [Link](https://reactrouter.com/api/components/Link), [hook](https://reactrouter.com/api/hooks/useViewTransitionState)). Good for carrying the car from home to `/blog`, not for the hero itself.

**8. Canvas / WebGL.** `three` 0.185.1 is 726 KB / 182 KB gzip ([bundlephobia API](https://bundlephobia.com/api/size?package=three)), absurd for one sprite. A hand-written 2D canvas is zero bytes of deps but client-only, needs `devicePixelRatio` scaling, rAF, and must stop drawing when off-screen or under reduced motion ([MDN optimizing canvas](https://developer.mozilla.org/en-US/docs/Web/API/Canvas_API/Tutorial/Optimizing_canvas)); a continuously running rAF loop is the mobile battery cost. Only reasonable if you want particles/smoke that SVG can't do cheaply.

**9. Video / animated image as a cheat.** web.dev's reference conversion: 3.7 MB GIF to 551 KB MP4 / 341 KB WebM; use `<video autoplay loop muted playsinline>` ([web.dev](https://web.dev/articles/replace-gifs-with-videos)). iOS allows autoplay without a gesture only for muted or silent video, needs `playsinline` to avoid fullscreen, and only plays while visible ([WebKit](https://webkit.org/blog/6784/new-video-policies-for-ios/)); Chrome: "Muted autoplay is always allowed" ([Chrome](https://developer.chrome.com/blog/autoplay)). (Low Power Mode blocking autoplay is widely reported but is not in WebKit's policy post.) Reduced motion: `<source media="...">` is honoured inside `<video>` per MDN ([source](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/source)), so you can serve a poster-only path. A `<video>` without `poster` is not an LCP candidate. Animated WebP: 96.18%, Safari/iOS 14+ ([caniuse](https://caniuse.com/webp)); animated AVIF: Firefox bug still open ([caniuse](https://caniuse.com/avif)). Remix's own homepage car is `/landing/remix-runner.gif`, a 384x384 GIF of 11 KB (measured today), which shows how cheap the cheat can be.

On either plan, no technique above adds server compute; the only bandwidth risk is a 300 to 750 KB WASM (Rive/dotLottie) per first visit, which is still nowhere near 100 GB.

## Recommendation for this site

1. **Inline SVG car on `offset-path` with CSS keyframes (2), gated by `prefers-reduced-motion`.** Zero JS, in the SSR HTML, Baseline, matches a line-art editorial aesthetic better than a photo-realistic asset, and the strict-TS/no-`as` rule never comes into play.
2. **Layer CSS scroll-driven animation (1) on top under `@supports`.** The same keyframes become scroll-scrubbed at 0 KB for ~85% of visitors today and Firefox in four weeks, with the time-based version as the fallback rather than a 17 KB polyfill.
3. **View Transitions via React Router's `viewTransition` (7) as the "spark" between pages.** Free, progressively enhanced, and lets the car carry from the hero into `/blog`; if you later want JS-level control, reach for Motion's `m` + `LazyMotion` (4.6 KB) before GSAP, since only Motion uses the native scroll timeline.
