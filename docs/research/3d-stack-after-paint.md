# 3D / shader background stack for jimmyvanveen.com, loaded after first paint (as of 2026-09-01)

Context: React Router 8.3 framework mode, SSR on Netlify Functions, React 19.2, Vite 8, strict TS with `as` banned. Builds on `research-animation-techniques.md` (CSS/2D options; it already priced raw `three` at 182 KB gzip and called it "no" for a single sprite). This report answers the different question: if a real 3D scene (stock car GLB) is wanted, which stack, and how to load it so SSR HTML and LCP never see it. "Measured" = downloaded from unpkg or bundled with esbuild 0.28 (`--bundle --minify --target=es2022`) and gzipped locally today; "timed" = parse + evaluate + renderer construction in headless Chromium (Playwright, SwiftShader, WSL2 desktop CPU, median of 5, download excluded; expect 3-5x on a mid phone).

## 1. Library choice

Raw three is the only option whose cost tracks what you use. R3F v9 pairs with React 19 only ("@react-three/fiber@9 pairs with react@19", [install docs](https://r3f.docs.pmnd.rs/getting-started/installation)); the npm peer range is `react >=19 <19.3` (fiber 9.7.0) and `react ^19` (drei 10.7.8) — fine for React 19.2.8 today, and there is already a `10.0.0-alpha.4` on the `alpha` tag. But fiber's JSX-to-three mapping (`<directionalLight>` etc.) resolves constructors off the whole `three` namespace at runtime, so the bundle metafile shows `three: 714 KB` minified inside the fiber build versus 602 KB for the hand-written one; fiber itself adds 149 KB min plus `three-stdlib` 69 KB. That is 100 KB gzip of tax to write `<mesh>` instead of `new Mesh()`, and it drags in a second copy of GLTFLoader (three-stdlib) unless you avoid drei. Babylon's own React guide is a `useEffect` + `useRef` wrapper around `new Engine(canvas)` ([Babylon docs](https://doc.babylonjs.com/communityExtensions/Babylon.js+ExternalLibraries/BabylonJS_and_ReactJS)), so it gains nothing on React and costs 787 KB gzip / 182 ms. A no-library WebGL2 shader (`canvas.getContext("webgl2")`, one fullscreen triangle, a fragment shader) is ~3 KB and is what to reach for if the effect is "ink wash / paper grain / gradient noise" rather than a car; WebGL2 is at 95.73% (Chrome 56, Firefox 51, Safari/iOS 15, [caniuse](https://caniuse.com/webgl2)). None of the four is SSR-safe by construction: they all touch `window`/`document` at import time, so the import must be a `import()` inside a client-only effect. Pattern for this repo: a `useHydrated()` built on `useSyncExternalStore(subscribe, () => true, () => false)` (React's documented way to keep server and first client render identical, [react.dev](https://react.dev/reference/react/useSyncExternalStore)), then `useEffect(() => { const id = requestIdleCallback(() => import("./scene").then(start), { timeout: 3000 }) ... })`. `requestIdleCallback` is at 80% and **disabled by default in Safari 13.1-27 and iOS 13.4-26.6** ([caniuse](https://caniuse.com/requestidlecallback)), so type-guard `"requestIdleCallback" in window` and fall back to `setTimeout(fn, 1)` after the first `requestAnimationFrame` (never an `as` cast). Do **not** add `<link rel="modulepreload">` for the scene chunk: modulepreload fetches, parses and compiles at high priority and MDN warns "you can't just preload everything" ([MDN](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Attributes/rel/modulepreload)); React Router's `<Scripts>` already emits modulepreload for the manifest, entry and route modules only ([components.tsx](https://github.com/remix-run/react-router/blob/main/packages/react-router/lib/dom/ssr/components.tsx)), and Vite preloads a dynamic chunk's dependencies only at the moment the `import()` runs ([Vite build.modulePreload](https://vite.dev/config/build-options)). That default timing is exactly what you want.

## 2. WebGPU in 2026

caniuse: 85.56% global; Chrome/Edge 113+, Chrome Android 151, Samsung 24+, Safari and iOS 26.0+, Firefox listed "disabled by default" ([caniuse](https://caniuse.com/webgpu)). The nuance on Firefox: Windows shipped in 141, "The WebGPU DOM API is now available on macOS 26 (Tahoe) on Apple Silicon" in 145 (2025-11-11, [release notes](https://www.firefox.com/en-US/firefox/145.0/releasenotes/)), all macOS in 147, and Linux/Android are still Nightly-only with Linux "expected in 2026" ([gpuweb Implementation Status](https://github.com/gpuweb/gpuweb/wiki/Implementation-Status)). Apple: "now shipping in Safari 26.0 for macOS, iOS, iPadOS, and visionOS" and "WebGPU supersedes WebGL ... preferred for new sites" ([WebKit](https://webkit.org/blog/17333/webkit-features-in-safari-26-0/)); MDN still marks it not Baseline and secure-context only ([MDN](https://developer.mozilla.org/en-US/docs/Web/API/WebGPU_API)). three's `WebGPURenderer` does fall back: the constructor sets `getFallback = () => { warn('WebGPURenderer: WebGPU is not available, running under WebGL2 backend.'); return new WebGLBackend(parameters) }` unless `forceWebGL` ([source](https://github.com/mrdoob/three.js/blob/dev/src/renderers/webgpu/WebGPURenderer.js)), and the manual says the fallback is "a crucial design decision". But the same manual says "The renderer itself is still in an experimental state", that `ShaderMaterial`/`RawShaderMaterial`/`onBeforeCompile` "are not supported" and must be ported to TSL, and that `EffectComposer` "is not supported" ([manual](https://threejs.org/manual/en/webgpurenderer.html)). Measured cost of that path is 285 KB gzip vs 159 KB and 67 ms vs 39 ms init. Babylon's port is "complete" with minor gaps ([status](https://github.com/BabylonJS/Documentation/blob/master/content/setup/support/webGPU/webGPUStatus.md)) but the library is 5x the size. Recommendation: ship `WebGLRenderer` now. A one-car, one-light, one-bloom scene gains nothing from WebGPU, GLSL keeps the hand-written-shader escape hatch, and the ~130 KB delta is the entire budget of the scene. Revisit when three drops "experimental" and Firefox Linux ships.

## 3. Cost model and the remix-website #501 checklist

Weight: JS 159 KB gzip (WebGL, bloom, Draco) + decoder: Draco `draco_decoder.wasm` 192 KB / 63.2 KB gzip + `draco_wasm_wrapper.js` 11.5 KB gzip (measured from `three/examples/jsm/libs/draco/gltf/`), or meshopt `meshopt_decoder.module.js` 29 KB / 7.7 KB gzip. Meshopt is the right decoder here: the spec is designed for "very fast decoding (... ~1 GB/sec ...)" and "byte-wise storage compatible with general-purpose compression" so Netlify's gzip/brotli stacks on top ([EXT_meshopt_compression](https://github.com/KhronosGroup/glTF/blob/main/extensions/2.0/Vendor/EXT_meshopt_compression/README.md)); `gltfpack -c` produces it and three supports it via `GLTFLoader.setMeshoptDecoder` ([gltfpack README](https://github.com/zeux/meshoptimizer/blob/master/gltf/README.md)). Budget the GLB at 300-800 KB for a low-poly stock car with 1-2 KTX2/WebP textures (`gltf-transform optimize --compress meshopt --texture-compress webp`, [gltf-transform CLI](https://gltf-transform.dev/cli)); skip `basis_transcoder.wasm` (245 KB gzip measured) unless textures dominate. Main thread: 39 ms parse+init on a desktop CPU means roughly 120-200 ms on a mid-range phone, which is why it must run after hydration and in idle time, not at module top level. Steady state is GPU-bound; remix's numbers before #501 were 120 renders/s idle at ~82% of a core on an M-series laptop. PR #501 ("Reduce landing page GPU and CPU usage", merged 2026-09-01, [PR](https://github.com/remix-run/remix-website/pull/501)) is the reusable checklist, all read from the diff:

1. **Frame governor**: `ACTIVE_MAX_FPS = 60`, `IDLE_MAX_FPS = 30`, `IDLE_AFTER_MS = 5000`; `nextRenderDeadline(now, deadline, idle)` skips rAF ticks that land before the next interval (15% tolerance), keyed on last pointer/scroll/prop activity. Result 119→59 active, 120→30 idle renders/s, idle CPU 82%→34% of a core.
2. **DPR cap**: `setPixelRatio(Math.min(devicePixelRatio, 1.5))` (was 2).
3. **Half-res bloom**: subclass `UnrealBloomPass.setSize` at 0.5x; cap `gl_PointSize` at 64 to bound overdraw.
4. **Device tier**: `lowEnd = matchMedia("(pointer: coarse)").matches || hardwareConcurrency <= 4 || deviceMemory <= 4` → halve particle count.
5. **Reduced motion = static frame**: under `prefers-reduced-motion` build a key from morph/theme/size and skip rendering while the key is unchanged.
6. **Skip idle passes**: disable the afterimage pass when damp ≈ 0 and the mouse-displacement sim once it has settled for 1 s.
7. **Capability gate**: throw and fall back to the static page if `EXT_color_buffer_float` is missing; drop `powerPreference: "high-performance"` (let the browser pick the GPU).
8. **Resize**: `setSize(w, h, false)`, coalesce `ResizeObserver` into the render loop (30 Hz live on fine pointers, 100 ms settle on touch), because `setSize` clears the canvas.
9. **Kill CSS work behind the canvas**: removed the full-width `backdrop-filter: blur()` and drove the brand-colour keyframe at 10 Hz via `animationDelay` instead of the compositor.
10. Tests for frame pacing and reduced-motion resize (`frame-governor.test.ts`, `home.test.e2e.ts`).

## 4. Mobile

A persistent rAF loop runs at the display rate ("The frequency of calls ... will generally match the display refresh rate", up to 120 Hz on ProMotion, [MDN](https://developer.mozilla.org/en-US/docs/Web/API/Window/requestAnimationFrame)); browsers pause rAF only when the tab is hidden ([Page Visibility API](https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API)), not when the canvas is scrolled away, so you own the pause logic: `visibilitychange` (Baseline since 2015) plus an `IntersectionObserver` on the canvas (Baseline since 2019, `entry.isIntersecting`, [MDN](https://developer.mozilla.org/en-US/docs/Web/API/Intersection_Observer_API)) that calls `renderer.setAnimationLoop(null)`. Better still, do not loop: three's `setAnimationLoop` only when something moves, otherwise render once; R3F's equivalent is `frameloop="demand"` + `invalidate()`, and its `PerformanceMonitor`/`regress` pattern scales `dpr` between 0.5 and 2 from measured fps ([R3F scaling](https://r3f.docs.pmnd.rs/advanced/scaling-performance)). Tiering inputs: `navigator.hardwareConcurrency` is Baseline (since 2022) but "the browser may ... report a lower number" ([MDN](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/hardwareConcurrency)); `navigator.deviceMemory` is not Baseline, Chromium-only, secure-context, and coarsened to powers of two ([MDN](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/deviceMemory)), so read it through a type guard on `"deviceMemory" in navigator` and treat absence as "unknown", exactly as #501 does with `?? 8`. iOS Safari: WebKit enforces a canvas memory ceiling ("Total canvas memory use exceeds the maximum limit (384 MB)" on iOS, [bug 195325](https://bugs.webkit.org/show_bug.cgi?id=195325), fixed for leaked canvases in 2023) and lost Metal-backed contexts on backgrounding in iOS 17.0 ([bug 262628](https://bugs.webkit.org/show_bug.cgi?id=262628), fixed 17.1). Handle `webglcontextlost` (Baseline, [MDN](https://developer.mozilla.org/en-US/docs/Web/API/HTMLCanvasElement/webglcontextlost_event)): `event.preventDefault()`, stop the loop, and on `webglcontextrestored` rebuild or simply show the poster again. Keep one canvas, dispose geometries/textures on unmount, and cap DPR at 1.5 so a 3x iPhone renders 1.5x, not 9x the pixels.

## 5. Fallbacks and the poster

Ship the poster in the SSR HTML as a real `<picture>`: `<source media="(prefers-reduced-motion: no-preference)" ...>` variants are honoured inside `<picture>` and the `<img>` is the fallback ([MDN](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/picture)). Two consequences you want: (a) the poster is an LCP candidate and `<canvas>` is not ("Canvas is not included", [web.dev LCP](https://web.dev/articles/lcp)), so LCP is the poster and finishes when the HTML's image does, independent of the 3D chunk — size it like any hero image (AVIF, `width`/`height`, `fetchpriority="high"`, well under 100 KB); (b) an image "with a low entropy" is excluded from LCP, so a flat-colour placeholder would silently shift LCP to the headline instead — fine, but know which one you are measuring. Reduced motion: render one frame and stop (`setAnimationLoop(null)` after the first render, or #501's static-key trick) rather than nothing, because the poster already covers the "nothing" case and a still 3D frame matches the poster. No WebGL / no `EXT_color_buffer_float` / context creation returns null: never mount the canvas, poster stays. No JS: same. The canvas mounts absolutely positioned over the poster with `opacity: 0`, fades in on the first rendered frame, and the poster remains in the DOM underneath as the context-loss fallback.

## 6. Netlify bandwidth arithmetic

Assumptions: scene assets (JS chunk + decoder + GLB + textures) are fingerprinted under `/assets/*`, which this repo already serves with `Cache-Control: public, max-age=31560000, immutable` (`netlify.toml`), so repeat visits cost zero bandwidth and no revalidation; only first visits count. Netlify's default browser policy is `max-age=0, must-revalidate` — do not put the GLB in `public/` without a matching header ([Netlify caching](https://docs.netlify.com/platform/caching/)). GB per month = MB × uniques / 1000, scene assets only, on top of the site's existing HTML/CSS/fonts/JS.

| Scene bytes per first visit | 2k uniques        | 10k uniques        | 50k uniques         |
| --------------------------- | ----------------- | ------------------ | ------------------- |
| 0.5 MB                      | 1 GB (20 credits) | 5 GB (100 credits) | 25 GB (500 credits) |
| 1 MB                        | 2 GB (40)         | 10 GB (200)        | 50 GB (1,000)       |
| 2 MB                        | 4 GB (80)         | 20 GB (400)        | 100 GB (2,000)      |

Legacy Free (accounts before 2025-09-04): 100 GB/month bandwidth, hard limit ([legacy plans](https://docs.netlify.com/manage/accounts-and-billing/billing/billing-for-legacy-plans/legacy-pricing-plans/)). Every cell except 2 MB × 50k fits with room; that one cell is the whole allowance before counting the rest of the site. Credit plan: 300 credits/month, hard limit ("all of your web projects ... are paused"), 20 credits/GB, 15 per production deploy, 2 per 10k requests, 10 per GB-hour of function compute ([how credits work](https://docs.netlify.com/manage/accounts-and-billing/billing/billing-for-credit-based-plans/how-credits-work/)). 300 credits is 15 GB if you never deploy; with ~8 Dependabot/feature deploys (120 credits) it is ~9 GB, so on the credit plan only 0.5-1 MB at 2k, and 0.5 MB at 10k, are safe, and 50k uniques is over budget at any size (50k × ~25 requests = 1.25M requests = 250 credits before a single byte). Practical target: **≤ 0.6 MB** of scene assets on first visit (160 KB JS + 8 KB meshopt + ~400 KB GLB/textures), served only to devices that pass the tier check, which also halves the bytes because coarse-pointer/low-core devices get the poster.

## Recommended stack for this repo

Raw `three` 0.185 `WebGLRenderer` + `GLTFLoader` + `MeshoptDecoder` + `EffectComposer`/`UnrealBloomPass` (or no post pass at all: a single `MeshPhysicalMaterial` car with one `DirectionalLight` and an `AmbientLight` is 153 KB gzip and one draw), imported from a dedicated route-level chunk via `import()`. No R3F (+100 KB, hydration gate needed anyway), no Babylon, no WebGPU yet. Keep the CSS/SVG car from the earlier report as the poster and the reduced-motion/no-WebGL/no-JS state; the 3D scene is the enhancement on top of it. Pin `postprocessing` only if you want its Zlib-licensed passes; three's own `UnrealBloomPass` avoids the `three <0.186` peer coupling.

Loading sequence, SSR HTML to first 3D frame:

1. **Server**: `routes/index.tsx` renders `<picture>` poster (AVIF/WebP, reduced-motion `<source>`, explicit `width`/`height`, `fetchpriority="high"`) inside `.home-cover`; no `<canvas>`, no scene imports anywhere in the route module graph. `theme-init.js` stays the only blocking script. LCP = poster or headline.
2. **Hydration**: React Router's `<Scripts>` modulepreloads entry + route modules only; `clientLoader.hydrate` runs as today. A `useHydrated()` hook (`useSyncExternalStore` with `getServerSnapshot: () => false`) gates a `<SceneMount>` component so the server and first client render are identical.
3. **Eligibility (synchronous, cheap)**: `matchMedia("(prefers-reduced-motion: reduce)")`, `matchMedia("(pointer: coarse)")`, `hardwareConcurrency <= 4`, guarded `deviceMemory <= 4`, `navigator.connection?.saveData` (guarded), and `document.createElement("canvas").getContext("webgl2")` returning null. Any hit: stay on the poster, never import.
4. **Idle scheduling**: `requestIdleCallback(load, { timeout: 3000 })` when present, else `requestAnimationFrame(() => setTimeout(load, 1))`. `load` = `import("~/scene/car-scene")` — Vite splits it into its own chunk and only then preloads its dependencies.
5. **Assets**: the chunk starts `fetch` of the meshopt-compressed GLB (and the 8 KB decoder) in parallel with its own evaluation; both under `/assets/*` with the existing immutable header. Textures WebP or KTX2 only if measured worthwhile.
6. **Init**: create the renderer with `alpha: true`, `antialias` off on coarse pointers, `setPixelRatio(min(devicePixelRatio, 1.5))`, `setSize(w, h, false)`; check `extensions.has("EXT_color_buffer_float")` before adding bloom; register `webglcontextlost` (`preventDefault`, stop loop, poster stays) and `webglcontextrestored`.
7. **First frame**: render once, then flip the canvas from `opacity: 0` to 1 over ~300 ms; the poster stays mounted beneath. If `prefers-reduced-motion` flips later, or the render loop is idle for 5 s, drop to 30 fps or one frame per change (#501 governor); pause on `visibilitychange` hidden and when the `IntersectionObserver` reports the canvas off-screen; dispose everything on route unmount.
